# Contributor Governance + Public Roadmap

Terraform Guardrail uses lightweight public governance so contributors can propose features,
report defects, request policy packs, and track roadmap progress without ambiguity.

## Delivered in v3.0 Development

- Contribution guide: [`CONTRIBUTING.md`](https://github.com/Huzefaaa2/terraform-guardrail/blob/main/CONTRIBUTING.md)
- Code of conduct: [`CODE_OF_CONDUCT.md`](https://github.com/Huzefaaa2/terraform-guardrail/blob/main/CODE_OF_CONDUCT.md)
- Security policy: [`SECURITY.md`](https://github.com/Huzefaaa2/terraform-guardrail/blob/main/SECURITY.md)
- Pull request template.
- Issue templates for bug reports, feature requests, and policy pack requests.
- Public roadmap metadata: [`.github/ROADMAP.yml`](https://github.com/Huzefaaa2/terraform-guardrail/blob/main/.github/ROADMAP.yml)
- CLA Assistant workflow for contribution sign-off.

## Contribution Flow

1. Open an issue for feature work, behavior changes, policy pack requests, or unclear bugs.
2. Use roadmap labels such as `v3-ecosystem`, `v4-intelligent`, `policy-pack`, and `integration`.
3. Submit a focused pull request with tests and documentation.
4. Sign the CLA when prompted.
5. Maintainers review compatibility, tests, documentation, and operational risk.

## Roadmap Hygiene

The roadmap is tracked in:

- [Roadmap](Roadmap)
- [v3.0.0 Ecosystem Release](Release-v3.0.0)
- [`.github/ROADMAP.yml`](https://github.com/Huzefaaa2/terraform-guardrail/blob/main/.github/ROADMAP.yml)

When a roadmap item ships, update all three locations plus the README roadmap table.

## Security Reports

Security-sensitive issues should not be opened as public GitHub issues. Follow
[`SECURITY.md`](https://github.com/Huzefaaa2/terraform-guardrail/blob/main/SECURITY.md).
